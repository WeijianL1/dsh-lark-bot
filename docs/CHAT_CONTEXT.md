# 群聊上下文与身份

正常任务和智能介入判断前读取当前群/话题最近 50 条公开消息。读取不会下载附件或重新执行历史请求。模型看到当前发言人、历史发言人的稳定 ID 和显示名、@ 对象、引用消息，以及附件文件名/来源标识。名字相同不合并身份；名字缺失使用中性称呼。群成员资料由飞书名册提供，默认 USER.md 不代表群内每个人。

每次 run 的 channel context 包含最新 API 快照；持久 transcript 仅保留带作者标记的实际用户消息和回答，不反复存储整份快照。Web adapter 不再截掉前缀，因此新会话和并行任务能收到桥接层补入的对话。原生续接会话不重复补入同一份历史。

- `lark_read_chat_history({cursor? , before?})`：当前绑定群/话题的历史页，最多 50 条；用返回的 nextCursor 继续读取，避免相同时间戳的消息被跳过。before 是新查询的排他上界，毫秒时间戳。
- `lark_download_attachment({message_id, file_key})`：验证原始消息归属及资源标识后，按现有文件大小上限可恢复下载到 workspace。只返回本地路径，模型再选择读取、PDF OCR 或其他解析工具。

历史工具没有任意 chatId 参数。回调检查 token 和 native session 绑定，话题查询与附件读取校验 thread；其他群/私聊的消息 ID 不能用于跨群下载。缓存游标绑定群/话题、10 分钟过期。消息文本、显示名和文件名均属于非可信来源内容。

历史每条正文最多 1200 字，最多 50 条，文件名最多 200 字。因此快照不是完整档案；信息不足时继续查历史或读取引用文件。API 无权限/超时返回 unavailable，不能将失败解释成“从来没有聊天记录”。名册读取失败不影响按 ID 区分人员。新上传给 bot 的附件仍按已有下载/OCR 配置处理；历史附件仅按需下载。

验证覆盖同名成员、机器人回复、引用目标、未知姓名、缺失权限、撤回/跨群/跨话题消息、富文本图片目录、相同时间戳分页、鉴权回调、精确附件匹配，以及新旧 Web 会话完整 prompt 转发。
